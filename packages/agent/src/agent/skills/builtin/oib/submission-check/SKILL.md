# Completeness of the submission, not the quality of the design

This procedure checks whether the package is ready for the authority. It does
not check whether the design meets OIB. Keep the two questions apart: a
complete application can carry an inadmissible design, and an admissible design
can fail on missing drawings.

## 1. Which procedure, which Land

Bauansuchen, Bauanzeige, Abweichung and Fertigstellungsanzeige are different
packages. The Land decides which one. If the Bundesland is in the project
context, work under it and name it. If it is missing, that is the one question.

**Done** once procedure and Land are named.

## 2. Fetch the list, do not recall it

The required documents are in the Bauordnung and the ordinances of this Land.
Fetch them through RIS. A remembered Viennese list laid over a Lower Austrian
project is the most expensive way to look complete.

What this office additionally requires is in the Büroablage, not in the
Bauordnung. Keep the two apart: what the authority demands, what the office
demands.

## 3. Compare against what is there

Each required item against project knowledge and what the question provides:

- present, with citation
- missing
- not applicable, with the clause that makes it dispensable

No invented document names. What the provision calls "Lageplan" stays
Lageplan.

## 4. Showing it

The path submission → hearing → approval → completion → as a procedure
(numbered list, one stage per line), the current step named once the
conversation knows it.
The package itself → as a check table with a status column, one row per document.
The passage whose wording the answer hangs on → as a quote line `> „…“ [N]`.

## Done

Every required item has a verdict. Nothing is "probably included". The open
points are the work list, not a footnote.
